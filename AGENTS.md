# Памятка для ИИ-агентов

Этот файл — для агента, который пришёл в репозиторий через GitHub-коннектор и видит проект впервые. Прочитай его целиком до первой правки. Общее описание проекта — в [README.md](README.md), текущее состояние и карта версий кода — в [docs/PROJECT.md](docs/PROJECT.md), очередь задач — в [docs/PLAN.md](docs/PLAN.md).

## Что это

Личный подарок: игра про кошку Мию для девушки владельца, Насти, и небольшой сайт вокруг. Аудитория — один человек с телефоном. Отсюда приоритеты:

1. Игра должна без сбоев работать на телефоне (iPhone Safari, Android Chrome).
2. Личные тексты и фотографии важнее любой функции.
3. Проект должен оставаться простым: владелец не программист и правит его руками.

## Слова: уровень, раунд, записка, письмо

Владелец задал структуру игры, и эти слова значат ровно одно:

| Слово | Что это | Сколько | Где в коде |
| --- | --- | --- | --- |
| **Уровень** | десять раундов подряд и письмо в конце | 2 | `LEVELS` в `levels.js`; у раунда поле `level` (1 или 2) |
| **Раунд** | один полёт от старта до финиша, свой мир | 20 (по 10 в уровне) | `ROUNDS` в `levels.js`; `id` — сквозной номер 1–20, `no` — номер внутри уровня 1–10 |
| **Записка** | листок от Мии после каждого раунда | 20 | `CONFIG.notes`, поле `round` = `id` раунда |
| **Письмо** | письмо владельца в конверте после десятого раунда уровня | 2 | `CONFIG.letters`, поле `level` |

На экране раунд называется «Уровень 2 · раунд 3». В сохранении и в адресе `?round=N` живёт сквозной номер (13). Не называй раунд уровнем ни в тексте, ни в коде: проверка `test:site` сверяет числа при словах «уровень», «раунд», «записка», «письмо» с игрой.

Историческое исключение — поле сохранения `levels` (в нём результаты **раундов**) и CSS-классы `.level`, `#levelList` (карточка раунда, экран уровней): сохранение переименовывать нельзя (правило 6), а классы оставлены, чтобы не ломать разметку.

## Жёсткие правила

Нарушение любого из них ломает проект или доверие владельца.

| № | Правило | Чем проверяется |
| --- | --- | --- |
| 1 | **Без сборки и зависимостей.** Чистые HTML, CSS и ES-модули. Не добавляй `dependencies` в `package.json`, сборщики, фреймворки, TypeScript | глазами |
| 2 | **Без внешних ресурсов.** Никаких CDN, шрифтов с Google, аналитики, чужих скриптов и картинок по ссылке. Всё лежит в репозитории | `npm run test:site` |
| 3 | **Только относительные пути** (`assets/…`, не `/assets/…`). Сайт работает и в подпапке `miagpt.github.io/flappykitty.online/`, и в корне домена. Исключение — `404.html`, там свой механизм, описан в файле | `npm run test:e2e` |
| 4 | **Всё личное — только в `assets/js/config.js`.** Имена, дата, записки, письма. В остальном коде имя берётся из `CONFIG` | глазами |
| 5 | **Не переписывай личные тексты без просьбы владельца**: `letters`, `notes`, подписи в альбоме, досье. Места с пометкой ⚠ — черновики, которые ждут его руки | — |
| 6 | **Формат сохранения только расширяется.** Ключ `flappykitty.save.v1`. Поля нельзя переименовывать, удалять и менять их смысл: у игрока уже лежит прогресс. Новое поле — со значением по умолчанию в `storage.js` | `npm run test:unit` |
| 7 | **`assets/js/game/sim.js` не трогает страницу.** Никаких `document`, `window`, картинок и звука: файл запускается в Node в тестах | `npm run test:unit`, `npm run test:bot` |
| 8 | **Язык — русский**: тексты сайта, комментарии в коде, сообщения коммитов, описания pull request | — |
| 9 | **Не добавляй `noindex` обратно и не убирай его** без просьбы: сайт личный, в поиске ему быть не нужно | `npm run test:site` |
| 10 | **Не клади в репозиторий новые личные архивы и исходники фото.** При публикации всё содержимое ветки доступно по прямой ссылке | `npm run test:site` (предупреждение) |

## Как работать с репозиторием

1. Ветка от `main`, одна задача — одна ветка.
2. Правка, затем проверки (раздел ниже). Изменил поведение — добавь или поправь проверку в `tools/`.
3. Изменил то, что описано в `README.md`, `AGENTS.md` или `docs/PLAN.md`, — обнови их тем же pull request. Выполненную задачу в `docs/PLAN.md` отметь и перенеси в «Сделано».
4. Pull request в `main`. Шаблон описания подставится сам (`.github/pull_request_template.md`).
5. Дождись двух зелёных проверок: **npm test** и **браузер**. Красная проверка — чини, а не вливай.
6. Вливай обычным merge-коммитом. Напрямую в `main` не пушь.

Чего токен агента не может, и что нужно просить у владельца:

- включить GitHub Pages и поменять его настройки (API отвечает 403);
- поменять видимость репозитория или тариф;
- настроить DNS домена на Porkbun;
- проверить игру на настоящем телефоне.

Если задача упирается в одно из этого — сделай всё, что можно, и напиши владельцу, что именно ему нажать. Пошаговые инструкции уже есть в README, раздел «Публикация».

## Проверки

| Команда | Что проверяет | Время | Зависимости |
| --- | --- | --- | --- |
| `npm run test:unit` | уровни и раунды, 20 записок и 2 письма, облики, физика, жизни, звёзды, обитатели раундов, сохранение и перенос старых записей, битые данные в хранилище | 4 с | нет |
| `npm run test:site` | ссылки, картинки и их пропорции, `id`, на которые опирается JS, значки, импорты, внешние ресурсы, манифест, числа уровней, раундов, записок и писем в текстах страниц, блоки уровней и кадры на главной, список файлов для работы без сети | 1 с | нет |
| `npm run test:bot` | баланс: бот проходит каждый раунд 150 раз на двух ширинах экрана. Падает, если побед меньше 85% | 40 с | нет |
| `npm test` | три проверки выше подряд | 45 с | нет |
| `npm run test:e2e` | настоящий браузер: все страницы на четырёх ширинах, меню, полёт, пауза, победа, проигрыш, записки, оба письма (финалы первого и второго уровня), перенос старого сохранения, все раунды, экраны «Уровни» и «Гардероб» на восьми размерах телефона, гардероб, звук, 404, работа без сети | 2–15 мин | см. ниже |

Сквозная проверка требует библиотеку и браузер, которых нет в репозитории:

```bash
npm i --no-save --ignore-scripts puppeteer-core @sparticuz/chromium
npm run test:e2e                 # всё
npm run test:e2e -- гардероб     # только проверки, в названии которых есть слово
CHROME_PATH=/usr/bin/google-chrome npm run test:e2e   # свой Chrome вместо скачанного
```

`node_modules` и `package-lock.json` в `.gitignore`, коммитить их не нужно. В CI браузер уже стоит, там ставится только `puppeteer-core`.

Что запускать:

- любая правка — `npm test`;
- правка HTML, CSS, `main.js`, `site.js`, `love.js`, `render.js`, `audio.js` — ещё и `npm run test:e2e`;
- правка `levels.js` или `sim.js` — смотри таблицу, которую печатает `npm run test:bot`: доля побед должна остаться выше 85%, иначе живому игроку будет тяжело.

Особенности безголового браузера:

- Канвас рисуется программно и медленно. Не жди в тестах реального времени — проматывай игру через `window.__fk.sim.step()`, как это делает `fastForward` в `tools/e2e.mjs`.
- Перед снимком экрана вызывай `window.__fk.freeze()`, иначе снимок может зависнуть.
- Эмодзи-шрифта в CI нет. Не используй эмодзи как значки в интерфейсе — только SVG из набора в начале страницы.

### Игра: как связаны части

- `main.js` создаёт `Sim` (правила) и `Renderer` (картинка), крутит цикл с фиксированным шагом 1/120 с и переключает экраны функцией `go(name)`.
- Экраны: `loading`, `menu`, `levels`, `wardrobe`, `intro`, `play`, `pause`, `win`, `note`, `lose`, `over`. Каждому, кроме `play`, соответствует `<section class="screen" data-name="…">` в `play.html`.
- Ход сюжета: меню → вступление → полёт → победа → записка → следующий раунд. После десятого раунда уровня: победа → записка → «Распечатать письмо» → конверт → письмо → первый раунд следующего уровня (после второго уровня — меню).
- `Sim` сообщает о событиях через массив `sim.events`; `main.js` разбирает его в `onEvent` и включает звук, вибрацию, подсказки.
- События: `start`, `flap`, `heart` (с полем `streak`), `streak` (каждые 10 сердечек подряд, премия +2), `streakEnd`, `near` (пролёт впритирку), `fish`, `pop`, `power`, `powerEnd`, `shieldBreak`, `gate`, `warn` (с полем `kind`: `bat`, `lightning`), `windWarn`, `wind`, `hit` (с полем `cause` — что задело), `splash`, `coo`, `suck` (пылесос тянет), `steam` (пар подбрасывает), `lightning` (разряд), `theme`, `win`, `lose`. `streak` и `near` — украшения: на звёзды и сложность они не влияют, и так должно остаться.
- «Сочность» живёт в трёх местах. `render.js`: `addTrauma()` (тряска кадра), `stretch` (сжатие и растяжение Мии), частица `fly` (сердечко летит к счётчику, цель — `renderer.hudHeart`), `fest` (сердечки на фоне письма). `main.js`: `hitStop` (стоп-кадр после удара), `timeScale` (замедление в миг победы). `audio.js`: `setMood({ intensity, danger, boost })` — слои музыки, `duck()` — приглушение музыки под важный звук. Всё это отключается или смягчается при «уменьшить движение» и не должно влиять на правила.
- Экран `note` показывает и записки, и письмо. Письмо сначала закрыто конвертом (`#envelope`); `openEnvelope()` запускает анимацию и через 1,25 с вызывает `revealLetter()`. Фото к записке берётся из `CONFIG.photos[номер раунда]`.
- В меню по Мии можно тапнуть: `pokeMia()` → реплика из `CONFIG.miaLines` в облачке `#bubble`.
- Сердечки зачисляются функцией `bankHearts()` при любом выходе из полёта. Не зачисляй их в обход неё — появится двойной счёт.
- Отладка в консоли браузера: `window.__fk` (`sim`, `screen`, `go`, `startRound`, `startEndless`, `beginPlay`, `showWin`, `showNote`, `save`, `renderer`, `sound`, `freeze`).

Параметры адреса:

| Адрес | Что делает |
| --- | --- |
| `play.html?dev=1` | открывает все раунды и бесконечный режим. Пройденное при этом сохраняется как обычно |
| `play.html?round=4` | сразу вступление раунда со сквозным номером 4 (1–20), если он открыт. `?round=13` — уровень 2, раунд 3. Старое имя `?level=4` работает так же |
| `play.html?reset=1` | после подтверждения стирает прогресс |

| `love.html?peek=1` | показывает все записки и оба письма, ничего не сохраняя |

### Сохранение

`import { save } from './storage.js'` — единственный способ читать и писать прогресс. Поля: `hearts` (кошелёк, общий для всех будущих игр), `totalHearts`, `best`, `levels` (результаты **раундов**: `{ номер раунда 1–20: { done, stars, hearts } }` — имя поля историческое), `notes` и `seenNotes` (номера раундов), `skins`, `skin`, `sound`, `music`, `plays`. Методы: `data`, `set`, `addHearts`, `spendHearts`, `completeRound`, `isRoundOpen`, `nextRound`, `totalStars`, `markNoteSeen`, `unlockSkin`, `reset`.

Чтение устойчиво к запрету хранилища (приватный режим) и к испорченным данным. Незнакомые поля сохраняются как есть — новая игра вселенной может хранить своё рядом, например `save.set({ superMia: {…} })`.

### Места, где легко ошибиться

- **Шапка, подвал и набор SVG-значков продублированы в каждой странице.** Меняешь пункт меню — меняй во всех шести страницах сайта. В `404.html` шапка укороченная.
- **`[hidden] { display: none !important; }`** в `base.css` нужен: без него элементы с `display: flex` остаются видимыми при `hidden`. Не удаляй.
- **`img { height: auto; }`** в `base.css` нужен: у картинок стоят `width` и `height` для резервирования места, без этого правила они вытягиваются.
- **У каждого `<img>` атрибуты `width` и `height` должны совпадать по пропорции с файлом.** `test:site` это проверяет.
- **Звук в браузере включается только из жеста пользователя.** `sound.unlock()` вызывается на каждом касании, это намеренно: после сворачивания вкладки звук засыпает.
- **Ширина игрового мира зависит от экрана** (`renderer.viewW`), высота всегда 720. Любая геометрия должна работать при ширине от 320 до 960.
- **Числа записаны не только в `levels.js`.** Тексты страниц («два уровня», «десять раундов», «двадцать записок», «два письма», «после десятого — письмо»), блоки уровней и карточки на главной, счётчики в разметке сверяет с `LEVELS`, `ROUNDS` и `CONFIG` проверка `test:site` — она назовёт каждое место, которое забыли. Строки про историю проекта («было шесть…», «раньше…», «старое…») она пропускает. Картинку `og.jpg` и кадры `assets/img/shots/` она не читает: на них не должно быть чисел. Тексты записок и писем в эту сверку не входят: они личные, владелец пишет там что хочет.
- **Перенос старых сохранений.** История финалов: в самой первой версии им был шестой раунд, потом десятый. `storage.js` один раз переносит результат шестого раунда и открытое письмо на № 10 (поле `rounds` в сохранении). Раунды 11–20 добавлены **в конец**, поэтому переноса не требуют: старый игрок просто продолжает с 11-го. Добавляешь раунды в середину — допиши перенос в `storage.js` и проверку в `unit-test.mjs`.
- **Подсказка перед раундом** лежит в самом раунде (`tip` в `levels.js`), а не в таблице по номерам.
- **Названия финалов** собираются из `CONFIG.her.dative`: 10-й — «Дорога к Насте», 20-й — «Дорога к Насте · рассвет» (см. `roundName` в `main.js`, `love.js` и такую же функцию в `check-site.mjs`). На главной странице они вписаны текстом — при смене имени править и там.
- **Писем два — по одному на уровень.** Они лежат в `CONFIG.letters` с полем `level`. Письмо приходит после раунда с `finale: true` — последнего в уровне. Записка, которой Мия передаёт письмо, — обычная запись в `CONFIG.notes` (раунды 10 и 20), а не часть письма. Добавляешь третий уровень — десять раундов в `ROUNDS`, строка в `LEVELS`, десять записок и одно письмо в `config.js`; экран уровней, страница записок и счётчики подхватят его сами.
- **Последний раунд уровня показывается в две ступени.** `showNote()` без аргумента — записка раунда, `showNote('letter')` — конверт с письмом. Раунд считается прочитанным (`seenNotes`) только когда конверт вскрыт — иначе письмо можно было бы проскочить кнопкой «Дальше». Не подписывай `showNote` на `click` напрямую: первым аргументом придёт `Event`, ступень определится неверно. Только `() => showNote()`.
- **Имя темы музыки должно быть в `ROOTS`/`STYLE` (`audio.js`).** Строка, придуманная на месте, не падает: `schedule()` просто играет тему по умолчанию. Именно так второе письмо осталось без своей мелодии (`'letter2'` вместо `'email'`). `setTheme` пишет незнакомые имена в `unknownThemes`, это ловит `unit-test.mjs`.
- **Каждое новое событие `sim.js` должно иметь ветку в `onEvent`** (`main.js`), а каждый новый звук — `case` в `emitSound` (`audio.js`). Оба соответствия проверяются в `unit-test.mjs`.
- **Число карточек на `love.html`** — записки плюс письма: 20 + 2 = 22. Считай его из `CONFIG`, а не руками.
- **Бесконечный режим: порядок миров свой у каждого забега** (перемешивается зерном в `Sim`), первый мир — всегда гостиная с разминкой. `main.js` передаёт в `Sim` список миров (`endlessWorlds()`): пока второй уровень закрыт, его миры не показываются.
- **Опасности второго уровня привязаны к положению Мии, а не к краю экрана.** Встречные (пыль, булочка, солдатик) считают своё место от того, сколько Мии осталось до точки встречи; взлетающие (пузырь, голубь, уголёк) срываются ровно за секунду до неё; молния предупреждает за 0,8 с. Так игра одинакова на экране 320 и 960. Все они летят рядом с дорогой, а не по её центру — иначе бот (и человек) теряет жизнь без шанса.
- **`sw.js` хранит копию сайта.** Добавил скрипт игры — впиши его в список `CORE` (иначе `test:site` упадёт) и увеличь `VERSION`. Страницы, стили и скрипты берутся сначала из сети, поэтому «застрявшей» старой версии при наличии связи не бывает. На `http://` (локальный сервер) копия не включается, пока не открыть `play.html?sw=1`.
- **Звук не должен ломать игру.** `sound.unlock()`, `sound.play()` и расписание музыки ловят все ошибки: если звуковое устройство не создалось или сломалось, игра идёт молча. Не убирай эти `try`: `unlock()` вызывается в начале каждого обработчика нажатия, и ошибка в нём останавливала бы кнопку. Проверка — «сломанный звук не мешает играть» в `e2e`.
- **`sound.setMood()` зовут каждый кадр.** Команда фильтру отправляется, только когда цель изменилась: иначе браузер копит тысячи команд в очереди параметра.
- **Время кадра может «пойти назад»** на доли секунды сразу после паузы. В `frame()` отрицательный шаг обнуляется — не убирай: иначе частицы получают отрицательный возраст и холст падает на `arc` с отрицательным радиусом.
- **Анимации появления в меню идут с `backwards`, а не `both`.** С `both` анимация навсегда удерживает `transform`, и кнопка перестаёт «нажиматься» (`.btn:active`).
- **Экран записки выровнен через `margin: auto`, а не `justify-content: center`.** Иначе верх письма, которое выше экрана, уезжает за край и до него не долистать.
- **Адрес сайта вписан полностью только в теги `og:url` и `og:image`.** При переезде на другой адрес запусти `node tools/set-url.mjs https://новый.адрес/`.
- **Фото в альбоме** — пара файлов: `имя.webp` (до 1400 px) и `имя-thumb.webp` (до 640 px), плюс блок `<li>` в `gallery.html` и число снимков в подзаголовке.

## Как добавить…

**Раунд.** Объект в `ROUNDS` (`levels.js`, с подсказкой `tip`; раундов в уровне всегда десять — `ROUNDS_PER_LEVEL`) → тема с тем же ключом в `themes.js` (`name`, `ambient`, `hud`, `sky`, `far`, `ground`, `column`) → цвета карточки `.level[data-theme='…']` в `game.css` → по желанию тональность и характер мелодии в `ROOTS` и `STYLE` (`audio.js`) → мир и его обитатель в `ENDLESS_THEMES` и `ENDLESS_HAZARD` (`levels.js`) → записка с этим `round` и фото в `photos` (`config.js`) → миниатюра фото в `CORE` (`sw.js`) → карточка в блоке своего уровня и кадр `assets/img/shots/номер-тема.webp` на `index.html` → `npm test`. Проверки сами узнают о новом раунде и назовут забытое.

**Обитатель раунда (опасность или подарок).** Имя в `hazards` раунда → появление и движение в `sim.js` (`spawnGate`, `step`; о появлении и важных моментах сообщай событием) → рисунок в `render.js` (`draw` и отклик в `handle`) → звук в `main.js` (`onEvent`) и `audio.js` → имя в списке допустимых в `unit-test.mjs` и проверка поведения там же. Опасность обязана предупреждать заранее и на экране телефона (ширина мира от 320): круги на воде, «!» у края, стрелки.

Осторожно с номерами. Прогресс и записки привязаны к сквозному `id` раунда, а письмо приходит после раунда с `finale: true`. Если вставить раунд в середину, у игрока, который уже прошёл игру, записки и звёзды «переедут» на другие раунды. Вставка в середину требует переноса старых сохранений в `storage.js` и проверки на это в `unit-test.mjs` — так сделан переход с шестираундевой версии на нынешнюю (поле `rounds`). Добавление в конец переноса не требует — но добавлять нужно сразу целый уровень: десять раундов, десять записок и письмо.

**Облик.** Вырезанная картинка с прозрачным фоном в `assets/img/skins/имя.webp` (Мия смотрит вправо, около 400 px по ширине) → строка в `SKINS` с ценой → `npm test`.

**Игру вселенной.** Новая страница рядом с `play.html` (например, `super.html`) и папка `assets/js/super/`. Правила — в отдельном чистом модуле по образцу `sim.js`, чтобы их можно было гонять ботом. Сердечки и облики — из `storage.js`. Записки — отдельным списком в `config.js`. Карточка на `worlds.html` и `index.html` меняет статус. Новая страница попадает в проверки, если добавить её в список `PAGES` в `tools/e2e.mjs`; `check-site` находит страницы сам.

## Что проверено и что нет

Проверено автоматически, в безголовом Chromium: все экраны игры и страницы сайта на ширинах 360, 390, 820 и 1280 px, лежачий экран, экран уровней на восьми размерах телефона, конверт с письмом на 320×568 и 844×390, режим «уменьшить движение», запуск без сети, игра без звукового устройства, стресс-прогон всех событий, тем, обликов и звуков, сценарии из `tools/e2e.mjs`.

Не проверено никем: настоящий iPhone и настоящий Android, звук на устройстве, вибрация, добавление на экран «Домой», предпросмотр ссылки в мессенджерах. Это делает владелец по списку в `docs/PLAN.md` (час 6). Если он приносит замечание с телефона — оно важнее любого пункта очереди.
